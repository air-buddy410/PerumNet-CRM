# PerumNet Hotspot Admin — Login & Dashboard Design Reference

Status: reusable frontend reference · 9 August 2026

This document captures the visual and interaction system used by the PerumNet Hotspot administrator login and dashboard. Reuse it as a presentation reference only: retain each target application's existing routes, authentication, RBAC, API/server actions, data model, and logout mechanism.

## 1. Design direction

The interface is a calm, operational PerumNet shell:

- A **dark teal, fixed desktop sidebar** establishes product identity and navigation.
- A **white topbar** carries page context, independent notifications, and the signed-in user's identity.
- The workspace uses a very light neutral background with lightweight white cards, tables, and forms.
- Teal is the primary action and selected-state color. Orange/red are reserved for operational status, not general decoration.
- Typography is compact, readable, and deliberately less “marketing” than a public portal.

Use the official PerumNet logo and favicon whenever the product is in PerumNet brand scope. Do not replace the logo with initials or an autogenerated avatar.

## 4. Admin login page

### Content and identity

Use this exact default copy for the Hotspot admin login:

```text
Masuk Ke PerumNet Hotspot System
Hotspot & Captive Portal Management System
© 2026 PerumNet. All Rights Reserved.
```

The form fields remain intentionally familiar:

| Field | Label | Input behaviour |
| --- | --- | --- |
| Username/email | `Username atau Email` | `type="email"`, `autocomplete="email"`, example placeholder `nama@email.com` |
| Password | `Password` | `type="password"`, `autocomplete="current-password"`, placeholder `Masukkan password` |
| Submit | `Masuk` | Uses the target application's real login endpoint/action |

### Desktop measurements

```text
Viewport
└── centered login wrapper: max-width 456px
    ├── brand/logo block
    │   ├── logo container height: 112px
    │   └── logo maximum: 220px wide × 112px high
    ├── gap below brand: 28px
    └── login card: width 100%, padding 32px, radius 17px
```

- The page fills the viewport with `min-height: 100dvh` and uses a centered grid.
- Desktop page padding: `44px 20px`.
- Use a subtle radial background tint, not an illustration or photo:

```css
background:
  radial-gradient(circle at 50% 33%, #dff6f2 0, transparent 31%),
  #f4fbfa;
```

- The brand is above—not inside—the form card.
- Logo lockup should be centered. If a small context label is needed, use a muted 9px, weight-800, uppercase label with 1.7px tracking.
- Use a 48px × 48px teal-tinted icon tile (rounded 13px) above the title. A login/arrow icon is appropriate.
- Keep the card strictly functional: no captive-portal selector, promotional content, static initials, or unrelated links.

### Login card rhythm

| Element | Specification |
| --- | --- |
| Icon tile | 48px square, `#E1F7F4`, 13px radius, teal icon around 25px |
| Title | 25px Plus Jakarta Sans, 800, margin top about 24px |
| Description | 14px DM Sans, `#7C8E91`, margin top 8px |
| First field | Starts about 28px below description |
| Field label | 12px DM Sans, 700, `#536C70` |
| Input | About 48px high, `13px 14px` padding, 8px radius, 1px `#DCE5E4` border |
| Field spacing | Label to input: 7px; field to field: 17–18px |
| Submit button | 100% width, minimum 48px height, margin top 2px |
| Footer | Centered, muted text, margin top 24px |

Input focus should be visibly teal without changing layout:

```css
input:focus-visible {
  border-color: var(--teal);
  outline: none;
  box-shadow: 0 0 0 3px #04a99f18;
}
```

### Login responsiveness

At `max-width: 760px`:

- Page padding: `30px 14px`.
- Keep the card within `calc(100% - 28px)`; it must never create horizontal scrolling.
- Card padding: `26px 24px`.
- Brand/logo container height: `98px`; logo maximum width: `190px`.
- Space below the logo: `22px`.
- Footer margin top: `20px`.
- Preserve at least a 44px pointer target for inputs and the submit button.

## 5. Dashboard shell

### Desktop layout

Use this structure on screens wider than 1100px:

```text
┌──────────────────── 264px ────────────────────┬──────────────── workspace ────────────────┐
│ Sidebar (fixed/sticky, full viewport height)   │ Topbar (74px, white)                       │
│ logo + HOTSPOT label                            │ page context · notifications · account     │
│ workspace/project selector                      ├───────────────────────────────────────────┤
│ RBAC-derived navigation                         │ light neutral content canvas                │
│ site / logout utilities                         │ cards, tables, forms, maps                  │
└────────────────────────────────────────────────┴───────────────────────────────────────────┘
```

```css
.dashboard-page {
  display: grid;
  grid-template-columns: 264px minmax(0, 1fr);
  min-height: 100dvh;
  background: var(--bg);
}
```

Do not allow the workspace column to force the page wider than the viewport; `minmax(0, 1fr)` is intentional.

### Sidebar

| Part | Specification |
| --- | --- |
| Width | 264px desktop |
| Position | Sticky/fixed at top; `min-height: 100dvh`; vertical scrolling allowed inside sidebar |
| Padding | `22px 15px 15px` |
| Surface | `#294B4E`, subtle right shadow `12px 0 28px #1E393812` |
| Brand row | 58px high, horizontal, 9px inner horizontal padding, 10px gap |
| Logo | Flexible, maximum 135px wide and 58px high |
| Product context | `HOTSPOT`, left divider `#FFFFFF42`, teal `#53CFC5`, 11px / 800 / 1.3px tracking |
| Workspace selector | About 20px from brand, 11px padding, 11px radius, translucent surface/border |
| Navigation item | Minimum 46px high, 12px padding, 9px radius, 12px / 700 |
| Selected item | Teal fill, white label/icon, soft teal shadow |
| Navigation group label | 9px / 800 / 1.1px tracking, `#9CB4B5`, e.g. `OPERASIONAL` |

The workspace/project selector uses a **Wi-Fi icon**, not a static initial. Recommended tile: 36px square, 9px radius, `#08AAA026` background, `#48CDC299` border, and a 19px icon in `#E7FFFC`.

The PerumNet logo row should include the context label `HOTSPOT`; it disambiguates the administration product without altering the official logo.

### RBAC navigation

Generate sidebar navigation from the authenticated user's permitted modules.

- A one-item category is a direct link.
- A multi-item category is a collapsible button with a chevron.
- Collapsible groups are closed by default unless one of their child routes is active.
- Expand/collapse uses a subtle 200ms fade/slide, with reduced-motion support.
- Selection must use the actual route, not only temporary local state.
- When a navigation item is selected on tablet/mobile, close the drawer.

Recommended operational grouping (adapt to the target project): data/visitor operations, users, project & gateway, team/audit, portal settings, external site, and logout. Do not invent CRM modules merely to mimic another product.

### Topbar and account controls

| Part | Specification |
| --- | --- |
| Height | 74px desktop; 66px mobile |
| Padding | `13px 32px` desktop; `10px 14px` mobile |
| Surface | White, 1px `#E4EEEC` bottom border, `0 5px 18px #27484508` shadow |
| Page title | 22px Plus Jakarta Sans / 800 desktop; 18px mobile |
| Context time | 11px muted text above title when useful |
| Content padding | `28px 32px 42px` desktop |

Place these independent controls at the right side of the topbar:

1. Optional refresh/status action.
2. **Notification button** — remains its own control and menu; do not nest it in profile controls.
3. **Account button** — show the real signed-in user's initial/avatar, name, and email/role when space permits.

The account dropdown must be populated from the actual authenticated session. It should contain profile access when available and invoke the existing real logout form/server action. It closes on Escape, outside click, and navigation.

On mobile, hide secondary text and the dropdown chevron in the compact trigger if needed, but keep the full information accessible inside the dropdown.

### Main content, cards, tables, and forms

- Canvas: `#F7FAF9`; main surface elements: white.
- Use 13px card radius, a 1px `#DFEAE8` border, and the soft card shadow listed above.
- Typical compact statistic card: minimum 108px high, `19px` padding, 14px internal gap.
- Use Plus Jakarta Sans for card titles and numeric emphasis; use DM Sans for labels and data.
- Let data tables scroll horizontally *inside their container* on narrow screens. Do not widen the page or shrink text below readability.
- Forms use the same input, focus, label, and primary-button language as the login page.
- Keep status badges compact, semantic, and text-labelled; do not rely on color alone.

## 6. Responsive behaviour

| Breakpoint | Required behaviour |
| --- | --- |
| `> 1100px` | 264px sidebar is visible; normal two-column app shell. |
| `<= 1100px` | Sidebar becomes a left overlay drawer (`transform: translateX(-102%)` when closed), with backdrop; workspace becomes one column. Header padding becomes 20px and main padding about `22px 20px`. |
| `<= 760px` | Header is 66px; main padding `18px 14px 34px`; compact topbar actions; responsive card grids; table/form overflow stays contained. |

Drawer rules:

- Open from a clearly labelled menu button.
- Use a backdrop and close on backdrop click, Escape, or successful navigation selection.
- Keep focus reachable and restore it to the trigger after dismissal where practical.
- Do not permit horizontal overflow behind the drawer.

## 7. Interaction and accessibility contract

### Required behaviours

- Keep admin login connected to the target app's real authentication endpoint/action. On success, redirect to the authenticated admin route.
- Restore the current session before rendering identity-specific actions, then apply RBAC to navigation and routes.
- Use dynamic name, email, role, project name, and project context; do not hard-code `Administrator` or a sample email.
- Keep notifications separate from the account dropdown.
- Workspace selection updates its dynamic title/context and applies the selected scope according to the target app's existing behaviour.
- Dropdowns and menus close on Escape, outside click, and navigation as applicable.

### Accessibility baseline

- Use semantic `<main>`, `<aside>`, `<nav>`, `<header>`, buttons, labels, and forms.
- Every icon-only action needs an accessible name (`aria-label` or visible tooltip/label).
- Use `:focus-visible` styles with sufficient contrast.
- Give click/tap controls a practical minimum target size of 44px, particularly login, drawer, notification, account, and logout controls.
- A chevron that controls a submenu must reflect state with `aria-expanded`.
- Never make status understandable only by color; include text such as `Online`, `Offline`, or `Tanpa pengunjung`.
- Honour `prefers-reduced-motion`.

## 9. Acceptance checklist

Before declaring an implementation complete, inspect real behaviour rather than relying only on a build/type check.

- [ ] Login works with the real endpoint/action and displays its genuine validation/error states.
- [ ] Official PerumNet logo renders crisply without a white box or stretched aspect ratio.
- [ ] Login fits desktop and a 390–430px phone viewport without horizontal scrolling.
- [ ] Desktop sidebar is 264px and the `HOTSPOT` context label is visible alongside the logo.
- [ ] Project selector uses a Wi-Fi icon, with project name/context sourced dynamically.
- [ ] Navigation reflects actual RBAC and active route; collapsible categories work by mouse, touch, and keyboard.
- [ ] Tablet/mobile drawer opens, closes via backdrop/Escape/navigation, and does not leave focus trapped or page overflow.
- [ ] Notifications still operate independently of the account menu.
- [ ] Account menu shows the real active account and real logout action; it closes on Escape, outside click, and navigation.
- [ ] Tables, maps, and forms remain usable at desktop, tablet, and mobile widths.
- [ ] Reduced-motion preference is respected and the browser console has no errors.

## 10. What may and may not change

**Keep consistent across projects**

- PerumNet palette, typography, official assets, login page hierarchy, 264px desktop sidebar, white topbar, responsive drawer behaviour, interaction dismissal rules, and independent notification control.

**Adapt to the target project**

- Actual title/copy where the product is not Hotspot, RBAC modules, page data, route names, project selector semantics, real auth flow, profile destination, notification contents, and backend/server actions.

**Do not copy blindly**

- Demo user names/emails, gateway data, visitor counts, project labels, API endpoints, client-side session storage, or logout implementation. Those are implementation details of the Hotspot product, not part of the design system.

## 11. Source-of-truth files in this implementation

For maintenance of the current Hotspot implementation, inspect these files before changing visual behaviour:

- `index.html` — login/dashboard structure and asset references.
- `styles.css` — canonical tokens and responsive rules. The later Hotspot admin override block is authoritative when older selectors differ.
- `app.js` — real session restoration, RBAC navigation, dynamic account/workspace labels, dropdown dismissal, and drawer behaviour.
